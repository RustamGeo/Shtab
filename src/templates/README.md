# Штаб

Проекты, подпроекты, задачи, заметки и карта идей. Вход — по почте и паролю. Устанавливается на компьютер, планшет и телефон, изменения синхронизируются между устройствами через Supabase. Работает и без интернета: правки сохраняются на устройстве и уходят в базу, когда сеть появится.

Настройка делается один раз и занимает около 15 минут.

---

## Шаг 1. База в Supabase

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → войдите через GitHub.
2. **New project**:
   - Name: `shtab`
   - Database Password: придумайте и сохраните (приложению он не нужен, но пригодится вам)
   - Region: **Central EU (Frankfurt)**
   - **Create new project**, подождите 1–2 минуты.
3. Слева **SQL Editor** → **New query** → вставьте весь текст из файла [`supabase.sql`](supabase.sql) → **Run**. Внизу должно появиться «Success».
4. Отключите подтверждение почты (приложение входит по почте и паролю, письма не нужны): **Authentication** → **Sign In / Providers** → **Email** → выключите **Confirm email** → **Save**.
5. Возьмите адрес и ключ: кнопка **Connect** вверху (или **Project Settings** → **API Keys** / **Data API**):
   - **Project URL** — вида `https://xxxxxxxx.supabase.co`
   - **anon** (или **publishable**) key — длинная строка.

   Ключ `service_role` / `secret` **не используйте** и никому не отправляйте.


## Шаг 2. Впишите адрес и ключ

Откройте файл [`config.js`](config.js) → карандаш **Edit** → впишите значения между кавычками:

```js
window.SHTAB_CONFIG = {
  url: 'https://xxxxxxxx.supabase.co',
  anonKey: 'eyJ...'
};
```

→ **Commit changes**.

## Шаг 3. Включите GitHub Pages

Репозиторий → **Settings** → **Pages** → Source: **Deploy from a branch** → Branch: **main**, папка **/ (root)** → **Save**.
Через 1–2 минуты приложение будет по адресу `https://ВАШ-ЛОГИН.github.io/shtab/`.

Если поменяете адрес сайта, впишите его в Supabase: **Authentication** → **URL Configuration** → **Site URL**.

## Шаг 4. Установите на устройства

| Устройство | Как установить |
|---|---|
| Компьютер (Chrome, Edge) | Откройте адрес → значок установки в адресной строке (монитор со стрелкой) → **Установить** |
| iPhone, iPad | Откройте адрес **в Safari** → **Поделиться** → **На экран «Домой»** → **Добавить** |
| Android | Откройте в Chrome → меню ⋮ → **Установить приложение** |

Откройте установленное приложение. На первом устройстве нажмите **Создать аккаунт** (почта и пароль от 8 символов), на остальных — **Войти** с теми же данными. На iPhone входите уже **внутри установленного приложения**, а не в Safari: у них разное хранилище.

Если приложением пользуетесь только вы: после создания аккаунта закройте регистрацию — **Authentication** → **Sign In / Providers** → выключите **Allow new users to sign up**.

## Шаг 5. Перенесите текущие данные

1. В старой версии (в Claude): **Резервная копия** → **Скачать копию** (или «Скопировать копию» и сохраните текст в файл `.json`).
2. В новой: **Резервная копия** → **Восстановить из файла** → выберите файл → **Заменить**.

Сделайте это на одном устройстве, остальные получат данные сами.

## Как это устроено

- `index.html` — всё приложение. `sw.js` — офлайн-кэш. `manifest.webmanifest` и `icons/` — установка.
- `src/` — исходники: из них собираются `index.html`, `sw.js`, манифест и иконки. Как собрать и выпустить новую версию — в [`src/README.md`](src/README.md).
- Данные хранятся в таблице `docs`: одна запись на проект и одна на карту. Правила базы пускают каждого только к его записям.
- Если включено шифрование (меню слева → «Включить шифрование»), каждый проект и карта шифруются на устройстве (AES-256-GCM, ключ из фразы через PBKDF2, 600 000 итераций). В базе — только шифротекст и служебная запись `crypt` с солью и проверочным значением; сама фраза никуда не отправляется.
- Без сети правки копятся на устройстве и отправляются при подключении. Если одно и то же изменили на двух устройствах, остаётся более поздняя правка.
- `.github/workflows/keepalive.yml` раз в день отправляет в базу лёгкий запрос, чтобы бесплатный проект не уснул (Supabase усыпляет его после 7 дней без обращений). GitHub может отключить такой сценарий, если в репозитории 60 дней не было изменений — тогда включите его снова во вкладке **Actions**.

## Если что-то не так

| Что видите | Что сделать |
|---|---|
| «Облако не настроено» слева внизу | Не заполнен `config.js` (шаг 2) |
| «Supabase ждёт подтверждения почты» | Выключите **Confirm email** (шаг 1.4) и войдите ещё раз |
| «Неверная почта или пароль» | Проверьте раскладку; если аккаунта нет — «Создать аккаунт» |
| Забыли пароль | Supabase → **Authentication** → **Users** → ваш пользователь → **Send password recovery** или удалите и создайте заново (данные удалятся вместе с пользователем — сначала сделайте резервную копию) |
| «Нет связи, повторю сохранение…» | Нет интернета или база уснула: откройте проект на supabase.com и нажмите **Restore** |
| «Нужна фраза шифрования» | Введите фразу шифрования (меню слева → «Нужна фраза шифрования»). Забытую фразу восстановить нельзя: данные в облаке останутся зашифрованными, поможет только незашифрованная резервная копия |
| Не видно новой версии | Закройте и снова откройте приложение — появится «Вышла новая версия → Обновить» |
